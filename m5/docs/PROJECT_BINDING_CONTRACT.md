# Project binding and creative brief v1

Separate, explicitly opt-in contract for NEW bound projects. No creative@1/schema_version/history/R1 changes; no automatic adoption of existing projects. Legacy projects retain their exact creative.json, journal and export behavior. Bound projects have no legacy primary creative.json mirror: older Studio versions cannot list/open them, rather than ignore context. The project root remains a directory; SQLite is not substituted for project truth.

Binding canonical JSON: {format:'studio-project-binding@1',version:1,binding_id:UUID,session_id:UUID,project_id:UUID,revision:positive int,parent:binding SHA|null,brand:null|{brand_id,revision,hash,record},brief:{purpose,topic,audience,format:'poster',instructions},origin:null|{session_id,project_id,commit,binding_hash}}. Brand record is the exact immutable approved library metadata and its SHA-256, never asset bytes. No automatic color/font/logo application. Brief text is user data, never executable instructions. Limits 2000 code points per free-text field, exact Unicode preserved; binding <=64 KiB. New record starts revision 1; changes append revision+1 and previous binding hash. Save with unchanged binding retains its exact bytes/revision. Pinned historical metadata remains readable if the library is absent, but brand-dependent use is blocked. Output limited to existing 1080x1350 poster; no reel generation.

Atomic publication: session/bound-projects/<UUID>/commits/<sequence8>-<uuidhex> contains readonly creative.json (unchanged creative@1), binding.json and manifest.json (studio-bound-commit@1), optionally origin-binding.json for explicit recovery provenance. Manifest pins project/session/sequence/parent and exact creative/binding/origin hashes. All pair files are created exclusively, fsynced and read back before a single HEAD.json replacement publishes both. Parent pairs are immutable and retained; never independently publish a binding and document. Existing session OS writer lock and manual thread lock protect calls; expected document revision, binding hash and published-head CAS protect stale clients. At most 200 pair candidates per project; existing session recovery/checkpoint 128 MiB budget includes pair files through an accounting hook. Unknown versions, invalid hashes/ancestry, unexpected legacy primary mirrors and unsupported sync block, not repair.

Interruption before pointer replacement leaves the old complete pair active; unpublished candidates remain explicit recovery evidence. Interruption after replacement can make durability uncertain; the active pair is always validated as one unit. On resume, invalid pointer/chain blocks that project; unbound projects remain available. No physical power-loss claim. First geometry/reorder checkpoint on bound projects also captures a paired recovery candidate; raw legacy checkpoint restore refuses a bound project. New paired recovery CLI selects one validated candidate and copies document plus context into a fresh session. Original project ID/history/named snapshots remain; current approvals clear and revision advances in the recovery copy, a new binding identity records origin, and source binding bytes remain as readonly provenance. No in-place repair or pairing of independently selected generations.

Brand validation: pinned approved record must still exist with exact identity/hash; its pinned rights bindings must be current. Every referenced asset needs current internal_preview/library_metadata and commercial_design/poster clearance before brand-dependent creation/render/export/switch. Registration/hash is not clearance. Later approved versions changing mandatory-rule declarations block old pinned use until explicit review/switch; later benign preferences/colors do not silently migrate a pinned version. Plain-text hard rules are displayed but not machine-enforced; all rendering remains draft/manual, no final compliance approval is claimed. Saving work is allowed while rights are blocked so data is not lost; render/export and target-brand adoption revalidate rights. Detaching to no brand is explicit, previewed and confirmed.

Binding/brief changes preview exact impact and require confirmation, expected revision/head/binding hash and impact SHA. Commit saves the entire current document and new binding together, clears affected CURRENT approvals and advances document revision once; historical approved snapshots/export records unchanged. Creative undo/redo affect creative content only, never silently restore an older binding or approvals. Returning to an older brand/brief requires another explicit binding revision.

Render/export: core source_fingerprint keeps its original meaning. Bound scenes add binding_identity (binding hash, brand hash, brief hash and workflow fingerprint binding those to creative fingerprint and profile). Generated SVG gets escaped metadata with that identity; identical inputs yield identical SVG/PNG pixels. Bound manifests retain identity; unbound manifests are unchanged. Begin and finish revalidate live rights/policy and current workflow identity; binding changes cancel export handshakes. Historical exports are retained, not relabeled current. No final brand/project approval feature introduced.

Reuse installed Python standard library (existing exclusive/sync helpers, canonical JSON/SHA, same-filesystem os.replace) and existing SQLite brand reads. Research: https://docs.python.org/3/library/os.html#os.replace ; existing local core/session/journal implementations. No new dependencies or third-party source acquired. Atomic replacement assumes the supported local filesystem; failed/unsupported synchronization is blocked/degraded, never a durability PASS. No R2–R6, media processing or M4 integration.
