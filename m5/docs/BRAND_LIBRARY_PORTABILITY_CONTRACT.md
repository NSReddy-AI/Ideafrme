# Brand library backup package v1

Separate from creative@1, history v3, R1 and the existing brand-record schema. No SQL database supplied by a package is opened/imported. Reuse installed Python zipfile (ZIP_STORED only; no decompression), strict canonical JSON, SHA-256 and existing SQLite transactions. Official research: https://docs.python.org/3/library/zipfile.html ; https://www.sqlite.org/lang_transaction.html . No new package or external service.

Package: ZIP with fixed timestamps/order/modes, no comments/encryption/ZIP64/compression/symlinks/directories. Max 72 MiB, 1101 members, 256 KiB central directory. EOCD/count/central bounds checked before constructing ZipFile. Never extract. Allowed member paths exactly manifest.json, records/<64 lowercase hex>.json and blobs/<64 lowercase hex>.bin. Duplicate/unlisted/missing entries, unsupported versions/flags/methods, overlapping/truncated entries and mismatched hashes/lengths refuse validation. Manifest canonical JSON <=1 MiB: {format:'studio-brand-backup@1',version:1,store_schema:{application_id,user_version:1},records:{hash:{path,bytes,sha256}},blobs:{hash:{path,bytes,sha256}},omitted_blobs:{hash:reason},heads:{brand UUID:record hash},assets:{asset UUID:record hash},rights_heads:{asset UUID:rights hash}}. Records canonical <=64 KiB and existing strict record schema; <=1000 records, <=100 assets, individual blobs <=8 MiB, total blobs <=32 MiB. All record references, unique identities, complete linear brand/rights ancestry, revision order, approval snapshot bindings and active pointer types validated. Orphan records/blobs and competing revision branches refuse. SHA proves package consistency, not publisher authenticity or permission.

Backup takes a consistent locked library snapshot. All immutable records/rights decisions and pointers are retained. Blob inclusion requires every registered identity sharing that blob to have a current grant with redistribute/library_metadata scope; otherwise the blob is explicitly omitted with reason. Missing source bytes/hash mismatch refuses backup. Inclusion is conservative transfer permission, not independently verified legal clearance. No blanket permission inferred from ownership labels or stored bytes. Manifest omissions are valid explicit dependencies, not silent truncation. A restore with a declared missing blob is blocked unless the same verified bytes already exist at destination. Asset kind is unverified and bytes are never decoded.

Preview validates full package before any destination initialization, returns source counts, hashes, omissions/missing dependencies, duplicate counts, lineage conflicts, proposed head actions and rights quarantines. It binds the plan to the package SHA-256 and destination fingerprint (all existing record/blob hashes and pointers). Existing store integrity is validated too. Preview never initializes an absent destination. No path input or hidden extraction.

Restore requires explicit acknowledgement plus preview package hash and destination fingerprint; revalidates package and plan under target lock. Existing identical records/blobs deduplicate. Immutable bytes never overwrite. Same-ID divergent asset/brand/rights histories block the entire transaction. For a common linear brand chain, preserve a newer local head or advance explicitly to the incoming descendant; exact duplicates do nothing. Preserve a newer local rights head (including revocation); never rewind. A new incoming grant or an advancing incoming grant produces an appended unknown-clearance quarantine event with empty scopes/destinations and null expiry. Existing exact same local grant is preserved, not recreated. Non-grant rights restrictions remain non-grants. All imported historic decisions/approvals stay unchanged. New local review is required to grant use after quarantine; old approval bindings remain stale even after regrant. Expired permissions never become valid through restored hash identity. No asset/project/creative use becomes enabled.

All insertions, appended quarantine events and pointer changes occur in one existing SQLite transaction. Stale preview, validation error, storage error or injected interruption before commit rolls back records/pointers. A previously absent destination may retain an initialized empty database on transaction failure; it is not a partial import and retry must be explicit. Existing records remain unchanged. Limits remain 100 assets/1000 records/32 MiB BLOBs/64 MiB DB; quarantine overhead can make a full-capacity import refuse and is disclosed in preview. No eviction, force-merge, rewrite, migration, automatic repair or physical power-loss durability claim.

Backups stored in a separate sibling <library-name>-backups directory under the isolated runtime tree. SHA-named packages created exclusively, read back and synchronized; duplicate verified package reused without overwrite. Max 20 packages/256 MiB aggregate. Incomplete failed-publication files remain for diagnosis; no evidence is deleted. Web operations use fixed routes, Host/Origin/CSRF, 100 MiB maximum JSON upload and 30-second client timeout; one request at a time. Explicitly selected package bytes stay in memory for preview/restore; no arbitrary filesystem paths or native media parser. UI package result is an in-workspace path, not an automatic browser download outside the workspace.

Known security boundary: trusted local actor and explicitly selected backup metadata, not a newly qualified hostile-media worker. Quotas/bounds are application checks, not Gate A resource enforcement. Unauthenticated checksums cannot distinguish maliciously rewritten but internally consistent history; imported grants are quarantined and external legal claims are unverified. Clean runtime/source/licensing closure remains open. No codec/model/paid service dependency.
