# Implemented contracts and compatibility

This inventory follows copied code, not aspirational universal specifications. Named source sections are relative to the checkpoint; PYTHON_INTERFACES.json supplies exact source lines. No M4 or M6 contracts/workspaces were opened.

## creative@1 and history

Actual format string is `ai-reel-studio/creative@1`, schema_version integer 1. Exact top-level keys: format,schema_version,id,project,brand,languages,views,assets,content,elements,revision,approvals,versions,history (creative_core/document.py and validation.py). project={name,outputs}; core accepts poster/reel outputs, languages en/te; views={id,width,height,language}. Core IDs are unique nonempty strings; UI project IDs additionally require canonical nonzero UUIDs. Core supports asset records {id,path,kind,sha256?} with confined existing paths and optional verified SHA; kind image/vector/logo/video/font/brand. Non-null core brand is {id,asset_id}, pointing to a brand-kind asset, NOT the SQLite brand record. Content={id,text,language,kind,source_ref?}; kind editorial/claim/quote, claim/quote require source_ref. Element={id,type,view_id,x,y,width,height,style,content_id?,asset_id?}; core types text/shape/vector/image/logo/video. Geometry must be finite, bounded numeric values; dimensions positive (number() uses absolute bound 1,000,000). Text binds content, media binds matching asset, shape is rectangle/ellipse. Core optional style fields fill,stroke,stroke_width,font_size,opacity,rotation,font_asset_id,shape,path have explicit type/reference validation; their presence in core does NOT mean Visual renderer supports them.

Visual/manual subset is narrower: assets=[],brand=null,outputs=[poster]; exactly 32 editorial content slots, 16 per language after UI creation; 64 layers maximum, 32 active text layers, only integer text/rectangle/ellipse geometry; x/y within ±1,000,000, width/height 1..4096, font_size 1..512, #RRGGBB fill. Text style is exactly fill/font_size, shape style exactly fill/shape. All historical transaction states and named snapshots must also satisfy this subset. Fixed renderer canvas1080x1350; two pinned fonts; text is not normalized. 8MiB UI document, 20,000 active code points, 64 explicit lines/text layer. No image import/decoding or arbitrary font use.

History v1 is the original {cursor,transactions} envelope; v2/v3 are explicit version fields. Supported versions are 1 implicit,2,3; unknown versions refuse. Each transaction has id,operation,before,after core snapshots; validation checks cursor/current state, valid ancestry and allowed operations. Existing add/move/restyle/edit_text/remove; v2 adds reorder; v3 adds geometry. Reorder requires full non-noop same-view permutation, current expected_revision; geometry nonempty unique IDs with complete x/y/width/height targets, current revision, same-view validation and non-noop. One atomic in-memory transaction/revision increment. First upgrade requires explicit acknowledgement and hash-verified immutable legacy checkpoint; history version remains sticky through undo/redo. Persisted reorder cannot change non-order properties; geometry cannot mutate anything beyond same-view geometry. Current approvals clear on operations/undo/redo; redo branches truncate on new operations. Named version snapshots/approval bytes remain append-only on save; past exports retained. Older readers reject newer envelopes, never silently downgrade. Checkpoint recovery excludes later edits and is explicit into a fresh session.

Core fingerprint is SHA256 of canonical CORE_KEYS only, excludes revision/current approval/history/version envelope. Approval records {id,reviewer,fingerprint} must match current fingerprint; these are local labels, not authenticated signatures. Core save preserves validated previous bytes, CAS expected digest and append-only named versions. Core's own directory fsync is best-effort; do not claim strict crash durability from core alone. Visual Journal adds checked sync, immutable intent/before/after/complete generation records, primary exact-byte comparisons, explicit interrupted/conflict states and a combined128MiB recovery/checkpoint/pair budget. Save errors block further mutation; explicit recovery copies do not rewrite source. Physical power loss remains unverified.

## Project binding v1

Exact separate record: {format:studio-project-binding@1,version:1,binding_id,session_id,project_id,revision,parent,brand,brief,origin}. UUID identities; positive binding revision; parent SHA|null; max64KiB canonical bytes. brief has EXACT purpose,topic,audience,format,instructions; text fields <=2000 Unicode code points, format poster only, no NUL/invalid UTF8. brand=null or {brand_id,revision,hash,record} pinning complete immutable approved SQLite metadata. origin=null or {session_id,project_id,commit,binding_hash} for explicit recovery. No change to creative@1.brand (still null in supported Studio projects).

Bound project truth lives in bound-projects/<UUID>/commits/<sequence8>-<uuidhex>/{creative.json,binding.json,manifest.json,origin-binding.json?}. Immutable files hash-pinned by studio-bound-commit@1 manifest with project/session/sequence/parent/creative_sha256/binding_sha256/origin_binding_sha256. Single replaceable HEAD.json={format:studio-bound-head@1,commit,manifest_sha256} publishes a complete pair. No legacy creative.json mirror. Up to200 retained candidates/project, shared recovery budget. Save validates chain, previous named snapshots and nondecreasing sticky history; unchanged binding stays byte-identical. Binding change appends revision+1,parent hash and advances creative revision, clearing current approvals. Expected document revision, binding hash, HEAD and impact digest reject stale clients. Switching needs impact preview/confirmation; Undo does not undo context. Parent generations never rewritten. Prepublication failure leaves prior pointer; postpublication uncertainty blocks until validated reopen/recovery; no automatic repair.

Rendering/creation/version switch/export revalidate current pinned brand and asset rights; saving blocked-rights work remains allowed. Later approved mandatory-rule changes block older pins; benign changes do not auto-migrate. Plain text hard rules require human review, not automated compliance. Regrant never resurrects an old rights-bound approval. Bound exports add studio-bound-render@1 identity: binding_hash,brand_hash,brief_hash,workflow_fingerprint over creative fingerprint+context+profile. SVG escaped metadata pins it; begin/finish recheck rights/context. Legacy source_fingerprint retains its meaning. Separate paired recovery copies selected full ancestry, clears current approvals and records origin. Older Studio cannot discover/open bound pairs: entire namespace is required in backups, not just creative.json.

## Brand Library v1

SQLite application_id0x42524131/user_version1; page_size4096,max_page_count16384; DELETE journal,FULL sync,temp_store MEMORY,timeout0. Exact tables: records(hash TEXT PRIMARY KEY,payload BLOB NOT NULL), blobs(hash TEXT PRIMARY KEY,data BLOB NOT NULL), heads(id TEXT PRIMARY KEY,hash TEXT NOT NULL REFERENCES records(hash)), assets(id TEXT PRIMARY KEY,hash TEXT NOT NULL REFERENCES records(hash)), rights_heads(id TEXT PRIMARY KEY,hash TEXT NOT NULL REFERENCES records(hash)). records/blobs have BEFORE UPDATE/DELETE abort triggers. heads/assets/rights_heads are application-validated pointers; SQL foreign-key declarations exist on heads/assets/rights_heads. No ORM. UTF8 compact sorted JSON, no Unicode normalization; per-record SHA identity and canonical readback,64KiB record cap.

Brand record={type:brand,brand_id,revision,parent,state,reviewer,approved_at,payload,bindings}; payload exact name,colors,typography:{english,telugu},mandatory_rules,preferences,inspiration,notes,asset_ids. <=16 unique colors,32 entries/list,64 asset refs. Save appends draft, approve appends approved revision after explicit acknowledgement/reviewer and live internal_preview/library_metadata checks. Bindings pin asset_id,sha256,rights_hash. Approved history never changes. Asset record={type:asset,id,name,kind,sha256,bytes,provenance:{owner,source,license}}. Opaque logo/image/font/template bytes1byte..8MiB; no binary rendering, decoding or font installation.100assets,1000records,32MiB distinct BLOBs,64MiB mainDB. These limits exclude filesystem/journal overhead and are NOT Gate A proof.

Rights record={type:rights,id,asset_id,previous,status,authority,evidence,scopes,destinations,expires}. status unknown/granted/denied. Allowed scopes internal_preview,commercial_design,redistribute,template_use,font_embed; destinations poster,reel,library_metadata. Grant requires authority,evidence,nonempty scopes/destinations and exact UTC expiry; other statuses carry no permissions/expiry. Latest event, scope/destination, wall-clock expiry and exact approval-bound rights hash all matter. Revocation appends denied; no deletion/rewrite. Labels/provenance/license claims are not authenticated clearance. Library approval is metadata-only; brand-bound draft workflow separately requires commercial_design/poster; registered assets still not applied.

Backup is studio-brand-backup@1/version1: deterministic ZIP_STORED logical entries/manifests, no archive extraction or direct database import.72MiB package,1101entries,256KiB central directory,1MiB manifest; assets included only where all identities sharing bytes permit redistribute/library_metadata. Missing omitted bytes block restore unless already verified locally. Preview verifies integrity/ancestry/conflicts before transactional restore, expected destination/package identities guard stale preview. Immutable versions never overwritten; divergent ancestry conflicts refuse. Revoked/expired rights remain denied, hash equality never grants permission. Metadata and opaque bytes stay separate from creative documents. See brand_portability.py and BRAND_LIBRARY_PORTABILITY_CONTRACT.md for exact member paths and restore rules.

## Manual restrictions and newer workflows

Poster-only: deliberate current Visual scope, not whole-product goal; core already represents reel but no M5 reel execution. Fixed1080x1350: current renderer/profile limitation; other core view sizes do not imply editor support. brand:null: legacy/manual restriction retained in all supported creative documents; separate pinned binding now supports compatible brand context. Editorial-only and empty assets: deliberate safe manual subset; separate catalogue registers rights-bearing opaque assets but does not apply them. Typography preferences are metadata, actual renderer remains two pinned font weights. Text wrapping/alignment are explicit editor-computed text/geometry changes, not new font/layout schema fields. Eventual media/reel capability remains required but gated, not silently dropped or already implemented.

## M4 compatibility assessment — no protected inspection

Confirmed on M5 side: M5 document, binding/brand namespace, UUID UI IDs, per-view typed layers, fixed renderer fonts/canvas, local approvals and paired recovery identities have the forms above. A generic file named project.json or brand.json cannot be assumed equivalent. M5 core brand reference is explicitly not the complete SQLite brand payload. These are confirmed M5 adapter requirements, not findings about uninspected M4 contents.

Unverified M4 risks: project.json field/types/version; brand.json semantics; identifier authority/collisions; scene/timeline versus views/elements and unit/time conversions; asset path bases/hash/rights provenance; fonts, shaping/canvas variants; approval authority and live revocations; immutable brand-version selection; history/recovery generation; render/export identity. No exact M4 schema, accepted revision or compatibility fixture was supplied/inspected, so bilateral incompatibility is NOT claimed. M4/M6 mappings, migrations and merge correctness remain unverified. Do not import opaque M4 records into SQLite or discard bindings/rights/history to make files open.

Safe later sequence: separately identify approved contract fixtures without opening protected workspaces; review explicit mapping/version matrix; build new adapter on copies with configurable roots under separate approval; test identity/rights/round-trip/rollback using synthetic fixtures; verify independent owned storage and export identities; only then request integration authorization. Never share mutable stores, point new software at accepted sessions or modify protected schemas for convenience.
